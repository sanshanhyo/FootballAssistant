## 本轮代码接入（不等于实机数据已打通）

- Windows 原生读取基础：`modules/game-bridge/windows-reader/` 提供 AMD64 PE 模块检查与进程内有界读取；不包含已验证 FM27 实体根、字段偏移或游戏加载器安装。
- `business-snapshot/0.1` 提供有类型的业务数据契约，独立于 UI/存档诊断流；包括负工资空间、工资周期/币种、比赛时间口径、缺失与过期状态。
- 认证只读接口：`GET /v1/reader/business/status`、`GET /v1/reader/business/snapshot`；客户端命令 `business-status`、`business-snapshot`。
- 完整 Agent 服务另有 `POST /v1/agent/business-advice`；只从服务端业务存储取事实，不接受客户端提交的事实快照。reader-only 服务不加载模型，也不暴露此建议入口。
- **目前没有注册经实机验证的 native producer**，业务能力明确返回 unavailable；这不是已经可用的 FM 数据 API。缺数据的建议请求不调用模型、不消耗模型预算。真实 producer 接入与实机验收仍待完成。
- 已有本地离线测试用于验证契约、认证、会话切换、重放/乱序、过期清理和建议门控；Windows 原生执行与 FM27 实机结果须分别记录，不从 Linux 测试推定通过。

## 数据验收范围

下列均为**必须取得实机证据的目标字段，当前未完成整类验收**。不因缺字段而擅自缩小需求；确实不可读时明确阻塞，而不是以人工输入或 UI 翻页替代完成。

| 数据类 | 最低必要字段与语义 |
| --- | --- |
| 球员 | 稳定球员 ID、姓名、所属球队 ID/名称、年龄、位置；技术/精神/身体属性；体能状态、伤病与停赛。球队引用不能仅靠同名文本连接。 |
| 候选球员合同与费用 | 合同所属对象、工资金额及周期/币种、到期日、身价与实际要价分别记录。未知要价不使用身价代填；不同工资周期不能直接比较。 |
| 球队财务 | 转会预算、工资预算与已用/可用工资空间，保留周期、币种与口径，不能从缓存 UI 文本推断。 |
| 世界时间与赛程 | 游戏内日期及时间、比赛标识、开赛日期/时间、双方球队和主客场。游戏时钟与现实采集时间分开。 |
| 战术 | 当前阵型、首发/替补及球员 ID 关联、各位置角色/职责、球队及个人指令；区分战术模板与实际选中阵容。 |

属性与状态的单位、枚举、量表及“已知为空”的含义必须写入字段契约；不能把未知伤病/停赛变成“健康/可出场”。采集范围、分页及截断必须显式可查，少量样本成功不代表全名单完整。

## 最短实现路径与接口交接

1. **先打通一个真实后台对象，再复用同类 schema。** 沿现有 injected bridge 寻找有安全证据的 typed/native object reader：稳定身份 → 球队/球员集合 → 字段值 → 关联对象。每一类对象只建立一套 schema/映射，通过 ID 查询和有界分页复用，不为每名球员、每张页面写规则。
2. **把已验证对象投影到稳定只读数据 API。** 先满足上述数据与桌宠消费边界；不是先造完整 SMAPI 式插件框架、通用反射 RPC 或任意内存调用平台。FMAPI 的更完整封装留到稳定数据 API 之后，不阻塞当前读取闭环。
3. **桌宠接真实受控查询，Agent 只做分析。** 沿用回环认证、有限查询与事件游标；reader 不调用模型。模型不接收任意地址/路径/native 调用能力，不自动改阵容、战术、转会或推进日期。建议与执行严格分离。

这里的“稳定数据 API”是待实现的业务契约，不是声称已有 `get_player(id)`。已有诊断接口见 [Companion / reader 交接](companion-reader-handoff.md)；实验性展示投影见 [display profile](display-profile.md)，不能升级包装成生产球员 API。

每次业务响应至少保留：schema 版本、数据源/adapter、游戏 build、session、snapshot/capture 标识、采集时间、连接状态、数据 freshness、字段来源与验证范围、partial/limitations、synthetic 标志。字段缺失用明确 unavailable/unknown/null 状态，不是零、空数组或上一会话缓存；连接在线不等于事实新鲜。换存档/重启必须隔离会话，分页不能混用快照，缺失 delta 字段不代表删除。

UI 抓取与模拟点击只用于诊断及人工交叉核对，**不能作为生产后台读取路线**。手工填表/导出不是用户已批准的验收替代方案。新发现的 `fmseasonhub-re` 只提供 Mac FM26 原生读取参考线索，不是 FM27 ABI、对象布局、许可复用或兼容性已验证；不据此改写当前状态，也不继续无目标地铺开调研。

## 三个目标的实机验收

以下复选框均保持未勾选，直到有针对待交付构建的真实记录。合成 fixture/单元测试用于回归，不能单独勾选。

### 1. 桌宠运行

- [ ] 在目标 Windows 测试机实际启动指定 commit 的桌宠，窗口/交互/退出可用，记录版本与证据。
- [ ] 当前 real adapter 连接指定 reader；展示真实连接、数据源和新鲜度，不静默回退 mock。
- [ ] 后端断开、重连、令牌轮换、切换游戏会话后状态正确，旧卡片和待返回结果不会串会话。

### 2. 后台读取全部所需数据

- [ ] 以上五类数据逐项核对真实字段、单位和稳定实体关联；在独立球员/球队样本上复验，而非只测试最初用于找字段的样本。
- [ ] 不打开逐个球员页面、不模拟 UI 翻页，也能按 ID/集合读到数据；切到无关页面后结果仍保持正确身份和来源。
- [ ] 在独立测试存档正常变化或重新载入后验证更新与 session 隔离；未变化、真实零值、缺失、stale、已知空集合分别验证。
- [ ] 全量集合/分页有覆盖证据；partial、失败、未支持的字段不被报告为完整读取。只读采集不改变业务状态，不用自动写入制造测试变化。

### 3. 提出有依据的建议

- [ ] 用真实读取结果完成选人/阵容或战术建议，能追溯所用球员属性、体能/伤停、赛程主客场及当前战术；明确事实与推断。
- [ ] 用真实候选球员合同、费用与球队预算完成引援/工资可行性判断；币种/工资周期一致，身价不冒充要价。
- [ ] 删除或使关键事实过期后，回答明确说明限制、拒绝无依据结论，不编造属性/预算，也不把 mock 数据用于真实建议。
- [ ] 记录输入 snapshot、引用字段、真实模型/配置、输出和人工核对结论；模型请求须处于明确授权额度内，不为验收自动提高预算。

## 验收记录交付格式

每项记录：目标/字段 → 代码 commit 与产物 hash → 游戏 build/session → 操作与预期 → 实际结果 → 私有证据引用/hash → 通过/失败/未测试及原因。另记采集与查询耗时，不预先虚构性能承诺。

原始存档、内存/packet、完整球员导出、token 和模型密钥不入 Git；公开记录只放脱敏结论与必要元数据。任何必需字段尚不可读时，Alpha 数据目标仍未完成，明确报告具体类/字段、当前证据和下一项最小验证；不以“桌宠能启动”或“测试全绿”宣布整个 Alpha 完成。

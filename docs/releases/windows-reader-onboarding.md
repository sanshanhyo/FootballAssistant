# Windows 0.0.1-alpha.2：赛外读取首装测试候选

本分支修复 **安装包缺少赛外读取 CLI、没有受信路径接线与首启验证入口**。
它不是已发布 Release；CI、合成夹具、离线自检都不是用户真实游戏验收。
不要求为读取赛外数据升级到 0.0.2。

## 这份包包含什么

- `OffseasonReaderCli.exe` 与自包含 win-x64 .NET 运行时，普通用户不需要
  Python、.NET SDK、开发目录或手工环境变量。
- `resources/reader-windows-x64/manifest.json` 记录完整文件 SHA-256、协议、
  源码 commit、运行时版本与目标平台。构建及打包后都会核验；缺文件、许可
  或哈希不符会阻止这次 CI 上传新的安装器。
- `licenses/` 保留实际 .NET Windows runtime pack 的许可和第三方声明，
  以及本项目许可。Windows .NET 二进制不因本项目 MIT 而被重新许可。
- 安装器版本 `0.0.1-alpha.2`；包内 `build-identity.json` 与 metadata artifact
  保存精确版本、Git commit 和 Actions run ID，区分同版本的不同候选构建。

**没有捆绑 BepInEx、Doorstop、比赛插件、游戏文件、生成的游戏 interop、
用户存档或采样。** 本修复不安装 loader，不写入游戏目录，不恢复旧 UI
bridge，不声称比赛实时读取已接通。

## 用户测试顺序

1. 完全退出旧桌宠。按自己的计划退出游戏并完成游戏完整性检查；本应用不会
   自动清除其他工具的 loader，也不会替用户修改游戏或卸载第三方组件。
2. 备份已有桌宠数据，然后安装这次 run 的 `Setup-x64.exe`。测试包不是并排
   安装应用；共享应用身份。卸载默认保留数据，不能当作干净隔离。
3. 在设置的 Windows 赛外读取入口发现或原生选择 `fm.exe`，检查组件和游戏
   版本后明确启用。路径由主进程处理；不让渲染页面提交任意执行文件路径。
4. 从正常入口启动游戏并加载存档，点击显式验证。没有游戏、多个候选进程、
   未知二进制、无当前记录或版本不匹配都应如实显示，不返回模拟成功。
5. 试问“当前游戏日期”；查询球员使用“读取球员 UID: 123”（改为真实已知
   UID）。球队与日历使用显式俱乐部 UID；不要靠自然语言姓名推断唯一对象。
6. 对照游戏中同一时刻的实际字段。记录测试包版本、commit/run、错误状态和
   是否有记录；不要公开上传密钥、完整存档、原始内存数据或私人路径。
7. 禁用读取后，应停止配置新的读取器调用。再次启用、重复点击、取消选择和
   关闭设置都需要实机回归；离线测试覆盖并不替代这些体验验收。

## 支持边界必须保留

只针对已知 `game_plugin.dll` SHA-256：
`bc940e472418fc5c214208d7cf30fecf600f689b6f9d71c11ba19a2df0fe057f`。
哈希不符时停止；不能为“可用”而跳过版本门禁。清单只包含这个公开指纹，
不含该游戏二进制。

读取仍为部分实验性数据，不是全量、完整或持续监控保证。候选经理、候选球队
不等于当前执教身份；进程会话不是存档身份；缺失字段不推断成零值。明确 UID
选择也不证明球员属于当前执教球队。比赛胜负主动对话/表情不在本次恢复范围。

## 自动化证据与仍待验证

CI 检查源码测试、自包含发布、实际 EXE `--version` 与 `--self-test` 协议、
打包后资源哈希及安装器 smoke。`--self-test` 输出
`status: offline_self_test, synthetic: true`，不枚举或访问游戏进程。
这些只能证明构建与受控链路，不证明真实游戏读取、字段语义或模型真实建议。

真实 Windows 首装、游戏哈希与进程匹配、当前日期/显式 UID 字段回读、窗口
交互及真实模型问答均留待用户验收。本次不发布签名更新 feed、不操作签名
密钥、不合并 main；portable 继续手动更新。

# M0 实机只读勘察计划

状态：**等待游戏实际文件可见，尚未执行实机勘察**。用户正在下载 FM27；本次未扫描安装目录、查找进程或检查游戏文件。FM27 与 Unity IL2CPP 均需通过实机证据确认。

## 启动条件

用户确认下载完成并指出实际安装位置后，先确认目录存在、可读且确为目标游戏。每次勘察记录本地日期、平台、工具与所读文件的相对路径。找不到文件、权限不足或产品/版本不符时记录未知并停止相关项，不通过更改权限、签名或安装状态“修复”。

## 只读清单

| 项目 | 可读取证据 | 要解决的问题 |
| --- | --- | --- |
| 产品与构建 | 游戏清单、应用版本信息、Steam 本地清单（如用户所指路径可见） | 实际是 FM27 吗？确切版本/构建是什么？ |
| 平台与架构 | macOS 应用包/可执行文件的 Mach-O 信息；Windows 文件头/PE 信息 | macOS 是 ARM64、x64 还是通用包？Windows 是否 x64？ |
| Unity 与后端 | 实际存在的 UnityPlayer、GameAssembly、libil2cpp、Metadata 目录及 `global-metadata.dat` 等候选；不得假定全部存在 | 是否 Unity？是否 IL2CPP？可读哪些版本证据？ |
| 文件指纹 | 关键二进制与元数据的只读 SHA-256、大小 | 后续结论对应哪个构建？仅记录必要文件，不复制游戏资产入仓库 |
| macOS 签名 | `codesign` 展示/验证结果、entitlements、hardened runtime、`xattr` 展示的 quarantine 状态 | 后续加载方式受到什么约束？只查看，不重签名、不删除扩展属性 |
| Windows 安全与加载条件 | 文件签名、游戏架构与已有保护声明 | 是否有明确的运行时加载限制？不添加排除项、不绕过保护 |
| 存档候选 | 用户指出的保存位置、文件名/大小/时间、只读格式特征 | 格式是否与参考解析器吻合？是否能安全取得用户指定副本？ |
| 两平台差异 | 分别取得的真实证据，缺失平台明确待核验 | 可否共用协议？哪些适配器必须独立实现？ |

M0 只提出备份/副本方案，不自动移动或改写原存档。未来经用户指定副本再做解析，先记录原件与副本摘要，避免解析器直接写入游戏正在使用的文件。

## 明确不执行的动作

不安装 BepInEx、MelonLoader、Frida 或其他注入/加载工具；不附加/调试游戏进程；不更改 Steam 启动参数、游戏文件、系统权限、签名、quarantine 或安全设置；不运行社区导出插件，不把 README 的支持声明视为本机验证。

## 输出与决策

输出一份本地只读勘察记录，含“已证实 / 未知 / 参考实现声称”三个证据等级，以及 macOS ARM64、Windows x64 分开的兼容矩阵。不得记录用户令牌、Steam 会话或完整个人路径到公开材料。

通过 M0 的条件是能明确实际产品/构建、平台架构、运行后端证据与存档候选，且所有未知有标记。若核心假设不成立，先修订架构与路线。若后续确需安装加载器或侵入式实验，先提出具体工具、版本、文件变更、退出/恢复方案，再由用户另行明确批准；M0 不代为批准。
